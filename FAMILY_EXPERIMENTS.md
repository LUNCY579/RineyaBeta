# Official-family experiment entry points

This successor branch adds **official Rineya dense-core** support without changing
the historical R2 experiment or its evidence. Use the new `family_pipeline` or
`family_native` entry point appropriate to the branch, not the old R2-only CLI.

See [the migration runbook](experiments/official_family_v1/README.md) for pinned
Supa Core 1.7 / Nimbus 1.6 / Halo 1.2 identities, authenticated asset restoration,
strict loading, fresh qualification, and bounded next-stage commands.

Model substitution is not evidence transfer or a performance claim. Neither an
asset inventory nor passing mechanical CI authorizes pretrained optimization.
